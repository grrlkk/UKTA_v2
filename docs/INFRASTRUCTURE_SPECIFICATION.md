## 프로젝트 개요

### 서비스 설명
UKTA(Unified Korean Text Analyzer)는 한국어 텍스트 분석 및 작문 평가를 제공하는 AI 기반 웹 애플리케이션입니다.

### 주요 기능
- **형태소 분석**: Bareun, UTagger를 활용한 한국어 형태소 분석
- **중급 분석**: 294개 이상의 언어학적 특징 추출
- **작문 평가**: 10가지 루브릭 기반 AI 평가 시스템
  - 표현(문법, 어휘, 문장 표현)
  - 구조(문단 내/간 구조, 일관성, 길이)
  - 내용(주제 명확성, 독창성, 서사)

### 논문 정보
- ACM/SIGAPP SAC 2025 AIED accepted paper (Oral)
- Paper: https://arxiv.org/abs/2502.09648

## 리소스 요구사항 분석

### CPU 요구사항
**Bareun 서버 (로컬 운영)**:
- 형태소 분석 추론: 2~4 vCPU
- BERT 기반 모델 추론: CPU intensive
- 동시 요청 처리: vCPU당 5~10 req/sec
- 권장: 최소 2 vCPU, 권장 4 vCPU

**백엔드 프로세스**:
- FastAPI 워커 프로세스: 2~4개 권장
- 형태소 분석 (UTagger): CPU intensive
- 특징 추출 및 통계 계산: CPU intensive
- 딥러닝 추론 (CPU 모드): 매우 느림 → GPU 권장

**프론트엔드 서빙**:
- Nginx/Caddy 등 정적 서버: 경량 (0.5 vCPU)

**⚠️ 중요**: Bareun 서버 추가로 **총 CPU 요구사항이 2~4 vCPU 증가**

### 메모리 요구사항

**⚠️ Bareun 서버 메모리 (로컬 운영)**:
- BERT 기반 모델 로딩: 약 800MB~1.5GB
- 형태소 분석 사전 및 규칙: 약 200~300MB
- Docker 컨테이너 오버헤드: 약 100~200MB
- 런타임 버퍼 (동시 요청 처리): 약 300~500MB
- **Bareun 총 메모리**: 약 **1.5~2.5GB**

**백엔드 모델 로딩 메모리 (initialize_models)**:
- KoBERT 모델: 약 400~500MB
- KeyBERT: 약 100MB
- Sentence Transformers (similarity model): 약 500~700MB
- GRU 모델: 약 50~100MB
- UTagger (형태소 분석기): 약 100~200MB
- 기타 라이브러리 및 캐시: 약 500MB

**총 백엔드 모델 메모리**: 약 **1.7~2.1GB**

**런타임 메모리**:
- FastAPI 프로세스 오버헤드: 프로세스당 200~300MB
- 동시 요청 처리 버퍼: 요청당 50~100MB
- MongoDB 커넥션 풀: 약 100MB

**총 런타임 메모리**: 약 **1~1.5GB**

**전체 메모리 요구사항 (Bareun 포함)**:
- 최소: **6~8GB** (Bareun 1.5GB + 백엔드 2GB + 런타임 1GB + 여유분 1.5GB)
- 권장: **12~16GB** (안정적 운영 및 동시 요청 처리)
- 최적: **16~32GB** (고부하 환경 대응)

### GPU 요구사항
**GPU 사용 시나리오**:
- 딥러닝 추론 속도 향상 (10~50배)
- BERT 모델 추론: GPU에서 50~200ms, CPU에서 500~2000ms
- GRU 모델 추론: GPU에서 10~50ms, CPU에서 100~500ms

**GPU 메모리**:
- 모델 로딩: 약 2~3GB
- 배치 추론 시: 추가 1~2GB
- 권장 GPU: NVIDIA T4 (16GB) 이상 또는 L4 (24GB)

**CPU vs GPU 선택 기준**:
- 동시 접속자 10명 미만: CPU 모드 가능
- 동시 접속자 10~50명: GPU 권장
- 동시 접속자 50명 이상: GPU 필수

### 스토리지 요구사항
**애플리케이션**:
- 백엔드 소스 코드 및 의존성: 약 500MB~1GB
- 프론트엔드 빌드: 약 50~100MB
- 모델 파일: 약 300MB
- 로그 파일: 약 1GB (월간)

**데이터베이스**:
- 초기: 1GB
- 1년 후: 5~10GB
- 3년 후: 50~100GB

**백업**:
- 데이터베이스 백업: 스토리지의 2배 권장

**총 스토리지**: **최소 50GB, 권장 100GB SSD**

### 네트워크 요구사항
**대역폭**:
- 사용자당 평균 요청 크기: 10~50KB (텍스트 입력)
- 사용자당 평균 응답 크기: 50~200KB (분석 결과)
- 동시 접속자 10명: 약 1~2Mbps
- 동시 접속자 50명: 약 5~10Mbps
- 동시 접속자 100명: 약 10~20Mbps

**권장 대역폭**: 최소 10Mbps, 권장 100Mbps

- OS: Ubuntu 22.04 LTS
- 용도: Bareun 서버 + FastAPI 백엔드 (GPU 추론)

**소프트웨어 구성**:
```
- Bareun 서버 (Docker): 포트 5757, 9902
  └─ BERT 기반 형태소 분석 + 맞춤법 교정
```

- CPU: 2 vCPU
- 메모리: 4GB RAM
- 스토리지: 20GB SSD
- OS: Ubuntu 22.04 LTS

**4. 네트워크**
- 공인 IP: 2개 (API 서버, 프론트엔드 서버)
- Load Balancer: 1개 (선택사항)
- 대역폭: 100Mbps

#### 예상 성능

  - BERT 추론 (GPU): 0.05~0.1초
  - GRU 추론 (GPU): 0.01~0.05초
  - 특징 추출: 0.3~0.5초
- 동시 처리 가능 요청: 30~50개

#### 장점
✅ 빠른 응답 속도로 우수한 사용자 경험
✅ Bareun 서버 통합으로 네트워크 오버헤드 제거

## 확장성 고려사항

### 수평 확장 (Scale-Out)
**백엔드 서버**:
- Load Balancer를 통한 트래픽 분산
- GPU 서버를 2~5대로 확장 가능
- 각 서버는 독립적으로 운영

**프론트엔드**:
- CDN 도입 (네이버 클라우드 CDN+)
- 정적 파일 캐싱
- 글로벌 서비스 시 지역별 서버 배치

**데이터베이스**:
- Replica Set → Sharded Cluster 전환
- 읽기 작업 분산 (Read Replica)
- 쓰기 작업 샤딩

### 수직 확장 (Scale-Up)
**GPU 업그레이드**:
- T4 (16GB) → L4 (24GB) → L40S (48GB)
- 추론 속도 향상 및 배치 크기 증가

**메모리 증설**:
- 16GB → 32GB → 64GB
- 더 많은 모델 캐싱 가능

### 비용 최적화 전략

#### 1. 개발/테스트 환경 분리
- 개발: CPU 모드 소형 서버 (월 50,000원)
- 운영: GPU 모드 권장 사양
- 총 비용 절감: 연 600,000원

#### 2. 예약 인스턴스 (Reserved Instance)
- 1년 약정: 10~20% 할인
- 3년 약정: 30~40% 할인
- 예상 절감액: 연 4,000,000~8,000,000원 (권장 사양 기준)

#### 3. Auto Scaling
- 피크 시간대(오후 2~6시)에만 서버 증설
- 새벽 시간대(0~6시) 서버 축소
- 예상 절감액: 월 300,000~500,000원

#### 4. CDN 활용
- 정적 파일 CDN 캐싱
- 트래픽 비용 절감: 월 30,000~50,000원

#### 5. 스토리지 최적화
- 오래된 분석 결과 아카이빙
- Object Storage로 이동 (저렴)
- 예상 절감액: 월 10,000~20,000원

### 모니터링 및 알림
**필수 모니터링 항목**:
- CPU/GPU 사용률
- 메모리 사용률
- 디스크 I/O
- 네트워크 트래픽
- API 응답 시간
- 에러율

**네이버 클라우드 서비스**:
- Cloud Monitoring
- Cloud Insight
- Cloud Log Analytics

**알림 설정**:
- CPU 사용률 80% 이상: 스케일 아웃 고려
- 메모리 사용률 90% 이상: 메모리 증설 고려
- 디스크 사용률 80% 이상: 스토리지 확장
- API 에러율 5% 이상: 긴급 점검

## Bareun 로컬 운영 vs 외부 API 비교

### Bareun 로컬 서버 운영 (현재 방식)

**장점**:
✅ **네트워크 레이턴시 제거**: 로컬 호출로 0.1~0.2초 절감
✅ **안정성 향상**: 외부 API 장애 영향 없음
✅ **데이터 보안**: 분석 데이터가 외부로 전송되지 않음
✅ **사용량 제한 없음**: API 호출 횟수 제한 없음
✅ **비용 예측 가능**: 고정 인프라 비용

**단점**:
❌ **인프라 비용 증가**: 월 71,000~148,000원 추가
❌ **리소스 관리 필요**: CPU/메모리 모니터링 및 관리
❌ **유지보수**: Docker 컨테이너 관리 및 업데이트

**추가 비용**:
```
최소 사양: 월 71,000원 (연 852,000원)
권장 사양: 월 148,000원 (연 1,776,000원)
```

---

### Bareun 외부 API 사용 (대안)

**장점**:
✅ **초기 비용 절감**: 인프라 비용 불필요
✅ **관리 부담 감소**: 서버 운영 및 업데이트 불필요
✅ **탄력적 확장**: 사용량에 따라 자동 확장

**단점**:
❌ **네트워크 레이턴시**: 외부 API 호출로 0.2~0.5초 추가
❌ **API 비용 발생**: 호출당 과금 (비용 변동)
❌ **사용량 제한**: API 호출 횟수 제한 가능
❌ **외부 의존성**: API 장애 시 서비스 영향
❌ **데이터 전송**: 분석 텍스트가 외부로 전송

**예상 API 비용** (Bareun AI 상용 API 기준, 추정):
```
호출당 비용: 약 10~20원 (추정)
일일 500건: 5,000~10,000원/일 = 150,000~300,000원/월
일일 2,000건: 20,000~40,000원/일 = 600,000~1,200,000원/월
일일 5,000건: 50,000~100,000원/일 = 1,500,000~3,000,000원/월
```

⚠️ **주의**: 실제 Bareun API 가격은 별도 계약이 필요하며, 위 비용은 추정치입니다.

---

### 비용 분기점 (Break-even Point)

**일일 요청 기준** (API 비용 호출당 15원 가정):
```
로컬 서버 고정비: 월 148,000원 (권장 사양)
분기점 호출 수: 148,000원 ÷ 15원 = 약 9,867건/월 = 약 329건/일

결론:
- 일일 329건 미만: 외부 API가 저렴
- 일일 329건 이상: 로컬 서버가 저렴
```

**권장사항**:
- **일일 300건 미만 (베타/소규모)**: 외부 API 고려 가능
- **일일 300~500건 (파일럿)**: 로컬 서버 권장 (비용 비슷하지만 안정성 우수)
- **일일 500건 이상 (정식 서비스)**: 로컬 서버 필수 (비용 및 성능 우위)

---

### 최종 권장사항 요약

**현재 구성 (Bareun 로컬 운영) 유지 권장**

**이유**:
1. ✅ **예상 사용량**: 일일 500~2,000건 → 로컬 서버가 비용 효율적
2. ✅ **성능**: 네트워크 레이턴시 제거로 0.1~0.2초 개선
3. ✅ **안정성**: 외부 API 의존성 제거
4. ✅ **보안**: 사용자 텍스트 데이터가 외부로 전송되지 않음
5. ✅ **확장성**: 트래픽 증가 시 추가 비용 없음

**대안 시나리오**:
- **극초기 베타 (일 100건 미만)**: 외부 API로 시작 후 트래픽 증가 시 로컬로 전환
- **비용 우선**: 최소 사양 (8 vCPU, 16GB)으로 시작 후 필요 시 GPU로 업그레이드
